# v4.0 Codex：接收 GLM 结果

按用户指定 Issue 和 handoff_id/结果评论读取原合同与真实最新 Git/PR/CI，确认接收的是当前有效阶段；过时交接不得覆盖新阶段。核查 GLM 已停、分支/SHA/dirty 归属，不能只凭“完成了”继续。

逐项核对 AC、实际命令与结果、尚缺证据、失败轮数。需要复杂修复由当前 Codex 直接承担并连续完成；只有明确施工再次应由 GLM 承担时才写新 Handoff、给三句并停。若当前 Codex 自己即可继续，就不要交给自己。

接收阻碍时优先重建最小复现，读已尝试路线，处理根因/设计判断，不让 GLM 机械重复同样失败。缺权限/依赖/授权时给准确恢复条件，不忙等。

实现和验证达到 REVIEW_READY 后，自动启动新的只读 reviewer 子代理。reviewer CHANGES_REQUIRED 时当前 Codex 直接接回整改；明确施工才再转 GLM。PASS 后再核对最新 SHA、验收证据、适用 CI 和平台门禁，全部满足才 MERGE_READY。

任何情况都不自动启动 GLM，不为等待而循环查询，不自动合并。

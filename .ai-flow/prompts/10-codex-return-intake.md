# v4.0 Codex：接收施工 / 审阅结果

按用户指定 Issue 和交接/结果评论读取原合同与真实最新 Git/PR/CI，确认接收的是当前有效阶段；过时交接不得覆盖新阶段。核查旧写入者已停、分支/SHA/dirty 归属，不能只凭“完成了”继续。

接收施工结果：逐项 AC、实际命令与结果、尚缺证据、失败轮数。需要复杂修复由本会话直接承担并连续完成；只有 next_actor 确实变为 worker 时才为明确施工写新交接、给三句并停。若当前 Codex 自己即可继续，就不要交给自己。实现和验证完成但尚未正式审阅时，再在 `codex-main → codex-review` 边界给手工新开独立会话的短句并停。

接收阻碍：优先重建最小复现，读已尝试路线，处理根因/设计判断，不让施工者机械重复同样失败。缺权限/依赖/授权时给准确恢复条件，不忙等。

接收独立审阅：确认审阅相对实现具有独立上下文、绑定最新 head/base、无 blockers 且关键证据足够。新提交或基线变化需更新验证/独立增量复核；不能自己把 finding 改成非阻塞绕过审阅。

只有独立审阅、验收证据、适用 CI 和实际门禁全部满足才 MERGE_READY，说明由用户合并。未满足时先判断 next_actor：若仍是当前 Codex 且在授权范围，直接继续整改/补证据；只有换 actor、外部等待或用户决策时才给可复制短句并停。任何情况都不自动启动其他会话或工具，不为等待而循环查询。

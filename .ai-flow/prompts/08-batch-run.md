# 批次执行：Codex / ZCode均可使用

读取当前仓库AGENTS、AI_CODING_PLAYBOOK、project.json及指定Goal/Issue队列。你是当前实际运行的Agent，不因角色名改变就声称启动了另一模型。

没有明确Goal且存在多个产品方向时汇总一次优先级问题；已有明确顺序就按顺序推进，不逐个询问“是否继续”。

1. 读取最新Issue/PR状态，选择分配给你、依赖已合并、无人正在处理的最高优先级任务。没有可靠原子领取机制时不和另一会话争抢任务，先使用明确不重叠的分配。
2. 核对基线和工作区，记录领取者/run ID/下一动作；使用独立分支。共享工作区永远单写入者，不动用户未提交改动。
3. 根据任务性质使用01或03实施，需调查用02；做到CI与证据就绪。不要一次把整个Goal塞进同一个无边界实现上下文。
4. 需要独立review时用真实已验证的接口发起；不能在实现会话中自批。无法调用则写HANDOFF_REQUIRED，保留交接单；在当前会话中仍可处理另一个无依赖且分配给你的任务，不越过依赖。
5. 整改用05或03；新SHA重新验证并请求独立增量复核。CI红、review等待或证据缺失不算完成。
6. 合并只按实际门禁与授权。auto-merge未启用时停在MERGE_READY等候维护者；不能自作主张打开设置。未合并依赖不提前实施。
7. 当前可执行队列耗尽、权限/额度阻断、需要人类决定或会话需要结束时输出一次批次汇总，保存断点并停止。没有常驻调度器就不承诺后台继续，不无限轮询。

批次汇总格式：已完成 / 待独立审阅 / 待合并 / 真正需人决定 / 下一Agent动作。只汇总需要人操作的工具交接，不把命名、实现方式、普通测试组织当成人的待办。

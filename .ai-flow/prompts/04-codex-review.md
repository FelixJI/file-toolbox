# Codex：独立正式审阅 / 整改后增量复核

在不同于实现者的独立会话/审阅任务中执行。只读审阅，不在正式审阅过程中直接改实现；需要修复时交05或03。不要沿用实现者自证结论。

读取当前Issue、适用AGENTS、实际base/head SHA、完整相关diff、相关未修改代码、测试和CI结果。必须确认正在审阅的是当前PR最新提交，而非聊天中陈旧摘要。

首次做完整范围审阅；整改后读取上一review的SHA到当前SHA的增量、对应findings及相关行为，不机械重审全部无关代码。base改变则检查集成影响，必要时扩大范围。

核对AC逐项证据、状态/数据流、错误处理、兼容、权限、持久化与回归；测试是否真的能验证声称行为。忽略不影响结果的命名/审美/P3建议。

每条finding给ID、文件位置/证据、触发场景、影响、严重级别和是否阻塞。P0/P1、AC缺失、必要验证缺失及可复现正确性/安全/兼容P2阻塞。不能因为默认GitHubreview只报P0/P1就遗漏需求验收；不能将P2一概留到合并后。

已有finding由实现者声明rejected时，核对其反证，不单凭一句“误报”关闭；修复项逐条核实新行为与测试。

输出：
1. reviewed_head_sha、reviewed_base_sha、独立会话说明（标识可得时写标识，不能伪造）。
2. 每条AC的证据/缺口。
3. findings及未解决blockers。
4. PASS / CHANGES_REQUIRED / INSUFFICIENT_EVIDENCE 三选一。

PASS必须无未解决阻塞项；不输出“批准但仍需修复”。信息无法访问、CI还没完成或关键路径没验证则INSUFFICIENT_EVIDENCE，不默认为通过。

将结果发布到当前PR（无权限则输出报告）。这份审阅结论不是GitHub批准身份，也不是自动合并授权；仍需项目实际门禁。
